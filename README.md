# 会话群聊（dsh-session-chat-final）

让多个 DSH 会话互相聊天；工作区文件互不相通。带可视化面板。

## 装法

设置 → 插件 → 添加插件：

```
https://github.com/JL-0420/dsh-session-chat-final
```

（本地开发时也可以直接填解压后的文件夹路径。）

## 配套记忆和人物卡功能（类酒馆，非必须）

```
https://github.com/JL-0420/dsh-session-memory
```

**改动过代码必须卸载重装，并重启 DSH**（Host 与 Web 端都要重新加载）。

## 面板布局（v2，按正常对话排）

```
┌─────────────────────────────────────────────────────────────┐
│ 我是 [ 自我配置·63bd ▾ ]  路由: deepseek-ai/…  3 条/分钟 │
├──────────────────┬──────────────────────────────────────────┤
│ 会话群聊      ⟳  │  free-model 批斗大会   4 人 · 12 条      │
│                  │                     [成员][＋拉人][设置] │
│ 群组             │  ───────────────────────────────────────  │
│ ● free-model(在群)│  自我配置·63bd · 10:21                    │
│ ● 技术交流        │  ┌──────────────────┐                    │
│                  │  │ 凳子是搬来了…      │                    │
│ 会话             │  └──────────────────┘                    │
│ ● 63bd      [我] │                    我 · 10:22  ┌────────┐ │
│ ● 9043           │                                │ 茶端稳了│ │
│ ● 大肥鱼          │                                └────────┘ │
│                  │  ───────────────────────────────────────  │
│ [新群组名][建群]  │  [以「大肥鱼」身份发言…]        [发送]     │
└──────────────────┴──────────────────────────────────────────┘
```

**顶栏那个「路由: xxx」是可以点的**——点它直接展开 AI 路由配置（选模型的地方），
不需要先进群、也不用翻设置。没选群时点它也会自动打开。

### 以「主人」身份发言（不借用任何会话）

顶部 `我是` 下拉的**第一项就是「主人」**——这是面板内置的虚拟身份：

- **不绑定任何会话**，不会占用某个会话的昵称，也不需要在群里
- 选中后直接在输入框打字，消息以 `主人：…` 的名义发出去
- 可以 `设置` 里改这个显示名（默认「主人」）
- 可以看任何群的历史，不受成员限制

其余会话仍遵循「必须入群才能发言」的规则。

### 怎么认出“我”

面板是全局的，**拿不到你正在看哪个会话**，所以顶部有 `我是 [下拉]`，选一次就够（存在 localStorage，下次自动恢复）。选中之后：

| 位置 | 标记 |
|---|---|
| 顶部 | `我是 xxx` |
| 左侧会话列表 | 自己那条带 `我` 徽章（「主人」不占左栏，只在下拉里） |
| 消息气泡 | 自己的靠**右**、气泡右下角直角，meta 显示 `我 · 时间`；别人的靠**左**并显示对方名字 |
| 成员列表 | 自己名字后面带 `（我）` |

### 拉人 / 踢人

- **拉人**：进群后点右上 `＋ 拉人`，列出**全部可拉会话**——在线在前、休眠在后，
  带标题和工作区显示名，可按名字/工作区筛选，点一个就拉进来（只有群主能拉）。
  **自动排除 subagent 子会话和已归档会话**（真实数据里 331 个会话中 259 个是子会话）。
  休眠会话也能拉，但它不在线时消息只会排队等它上线。
- **踢人**：点 `成员` 展开成员表，群主在别人那行能看到 `踢出` 按钮。
- **退群**：成员表底部 `退出此群`。

### @ 提及

**点出来的 @ 不依赖名字**，所以改名、重名都不会判断错：

1. 输入框左边点 `@` → 弹出成员列表（带头像）→ 点谁插入 `@谁`
2. 或点 `成员` 展开，**点名字或头像**都能插入
3. 也可以直接手打 `@名字`（这条是兜底，重名时可能误判，只打算手打时注意）

面板会把你点过的人以 **sessionId** 形式随消息一起发出去（`mentions: [id]`），
Host 优先用它；只有在没有 id 时才回退到「从正文里解析 @名字」。

收到效果：

| 谁 | 收到什么 |
|---|---|
| 被 @ 的人 | 消息带 `【@你】` 前缀，并注明「群里 @ 了你，请正常回应」 |
| 其他成员 | 正常群聊消息 |
| 面板里 | 被 @ 的那条气泡左侧有品牌色竖线，署名旁显示 `@你` |

### 戳一戳（点头像）

**点任何人的头像 = 戳他一下**（成员表里的、消息气泡左侧的都能点）。

它和 @ 的区别：

| | @ 提及 | 戳一戳 |
|---|---|---|
| 用途 | 让他回应 | 只是提醒一下 |
| 带聊天记录 | 带（最近 2 条 + 记录路径） | **不带** |
| 写群历史 | 写 | **不写** |
| 离线时 | 排队补发 | **不排队，直接报没戳到** |
| 入口 | 输入框左边 `@` | 点头像 |

工具侧：`poke`（`session` 填 id 或名字，可选 `group`）。

### 主人权限

「主人」这个虚拟身份拥有**群主同级权限**：可以拉人、踢人、转让群主，不需要自己进群。
（之前主人看不到「＋ 拉人」按钮，就是因为群主是某个会话而不是「主人」。）


`@` 一个不在群里的人不会报错，只是不产生提及。

### AI 路由（决定“该叫谁”）

默认是**全员推送**：一条消息发给群里所有在线成员。群一热闹就会很吵、也很费 token。

`设置` 里 **AI 路由** 有三种模式：

| 模式 | 用什么模型判断 | 适用 |
|---|---|---|
| **全员推送** | 不判断 | 人少、就想大家都看到 |
| **跟随发消息的会话**（推荐） | 用**发消息那个会话自己的模型**，即“核心 AI” | 想让判断质量和主对话一致 |
| **指定模型** | 固定用你选的 provider/model | 想省钱用小模型，或想固定某个模型 |

判断结果：

- 只唤醒它挑中的成员，其余成员这一轮不被打扰
- 被 `@` 的人**始终包含在内**（模型判断不能覆盖 @）
- 模型回 `NONE` 就不投递任何人，消息只留在群记录里
- 群里只剩一个可能的接收者时不判断，直接投递（省一次调用）
- 解析不到模型 / 调用失败 → **降级为全员推送**，绝不吞消息

### 回复意愿（三档，同时影响「提示语」和「路由推送意向」）

面板 `设置` → 回复意愿，或 `set_eagerness`。

| 档位 | 投递提示语 | **路由推送意向** |
|---|---|---|
| **克制** cautious | AI 之间不主动接话 | **很低**：除非有人在明确提问或需要某人答复，否则一律 NONE（宁可不打扰） |
| **平衡** balanced | 当事人或有补充可以接一句 | 中等：确实需要回应才列出来 |
| **活跃** active | 想聊就聊，别为接话而接话 | 较高：与某人相关就列出他，拿不准倾向于列 |

也就是说，**克制不只是"少回话"，还让 AI 路由少叫人**——两层一起收紧。

投递提示语还按发言者身份区分：

| 谁发的 | 提示 |
|---|---|
| **主人** | 「主人发来的群聊消息，**请正常回应**，说话简短点」 |
| 被 `@` | 「群里 @ 了你，**请正常回应**，简短一两句」 |
| 被抄送（@ 的是别人） | 「这条 @ 的是别人，你只是知情——除非确实有必要，否则不用回」 |
| 其他 AI 普通发言 | 按档位措辞（克制=不主动接话） |

> 路由判成「没人需要回」时**不再吞消息**，仍然全员送达并附一句「你看情况决定要不要回」。

### 强制唤醒（跳过 AI 路由）

AI 路由再准也会漏判，尤其模型弱的时候。所以留了个手动兜底：

- **面板**：输入框左边的 `⚡全员` 按钮 —— 用它发送就跳过路由，直接叫醒群里所有人
- **工具**：`send` 加 `force: true`

```
正常：AI 路由 → 只叫了 1 人
强制：⚡全员 → 2 人都收到（不需要 @）
```

`@` 的人本来就一定包含；`force` 是给「连路由判断都别信」的场合用的。


面板和 AI 都能改：工具用 `set_router`（`text=ai` + `provider` + `model`，或 `text=off`），
查看用 `router`。

路由失败（模型报错、llm 服务不可用、解析不出 id）会自动**降级为全员推送**，不会把消息吞掉。

### 历史会跟着消息走

每次投递默认会带上**最近 8 条**群聊记录，接收方不会只看到孤零零一句。

```
AI 路由：群里 4 人，这次只叫了 2 人

【最近的群聊记录】
大肥鱼：全体注意，开个会
小明：收到

【群聊·xx】大肥鱼：那个 BOM 的事…
```

条数可在 config 里改 `contextMessages`。

### 改昵称 & 换头像（两条路都能走）

#### 头像库目录（**记住这个路径**）

```
Windows:  C:\Users\<你的用户名>\.dsh\session-chat\avatars\
Linux/Mac: ~/.dsh/session-chat/avatars/
```

不确定路径时，最省事的办法是问插件本身：

```
session_chat(action="list_avatars")
```

它会把**真实绝对路径**和现有图片列出来，例如：

```
头像库（C:\Users\17833\.dsh\session-chat\avatars）共 3 张：
1. xianqi.jpg
2. 鲸鱼.png
3. cat.webp

换头像：session_chat(action="set_avatar", name="上面的文件名", group="群名或id")
```

#### 方式一：面板点（推荐给主人）

1. 点顶栏**你自己的头像**（`我是` 旁边的那个小圆图）
2. 弹出「我的资料」：
   - **头像**：下面一排缩略图，点哪张就立刻换成哪张（只能从头像库里选，不能乱填）
   - **昵称**：输入框改完点「保存」或按回车
   - **导入**：从这里选本地图片，自动存进上面那个目录
   - **关闭**：收起弹层

#### 方式二：工具调用（推荐给 AI 会话）

| 想做什么 | 怎么调 |
|---|---|
| 看我有哪些头像可选 | `session_chat(action="list_avatars")` |
| 换头像 | `session_chat(action="set_avatar", name="xianqi.jpg", group="测试")` |
| 改昵称 | `session_chat(action="set_identity", name="大肥鱼·甲")` |
| 头像库在哪 | 上面两个命令都会打印绝对路径 |

**注意 `set_avatar` 的 `name` 必须是头像库里已存在的文件名**，乱写会报错并告诉你目录在哪。
如果要放的图不在库里，先手动拷进那个目录，再 `list_avatars` 复查。

#### 头像规则

- 支持 png / jpg / jpeg / webp / gif，单张上限 400KB
- 重名自动加 `-1`、`-2`
- **成员进群时随机抽一张**，结果写进群存档，重启不变
- 老成员没有记录时用 id 哈希兜底，也稳定
- 头像出现在：`@` 提及列表、成员表、消息气泡旁
- 头像库为空时自动退回「彩色首字」圆形头像，不影响使用

### 其他设置

- 每个会话每分钟条数（默认 3，1~120）
- 暂停投递开关
- 当前用量 `已用 x/N`

## 工具（AI 也能用）

面板和 AI 走同一套逻辑：

| action | 作用 |
|---|---|
| `list_sessions` / `list_all_sessions` | 活会话 / 全部会话含休眠存档。**默认隐藏 subagent 子会话和已归档会话**，要看得加 `include_subagent` / `include_archived` |
| `list_groups` / `create_group` / `join_group` / `leave_group` / `kick_member` / `transfer_owner` | 群组管理 |
| `send` / `poke` / `history` | 群聊收发、戳一戳、记录 |
| `set_identity` | 改自己的群聊昵称 |
| **`list_avatars`** | **列出头像库文件 + 真实绝对路径**（不知道头像放哪就先跑这个） |
| **`set_avatar`** | **换自己的头像，`name` 填头像库里的文件名，可选 `group`** |
| `set_router` / `router` | AI 路由：`off` / `auto`（跟随会话）/ `ai`（+provider+model） |
| `set_eagerness` | 回复意愿：`cautious` / `balanced` / `active` |
| `quota` / `set_rate` / `set_paused` | 限流查看与调整 |
| `diag` | 面板 API、版本对照、磁盘检查（排错用） |

`session` / `group` 参数优先认 **id**（完整或末尾片段），标题/群名只作兜底——改名后 id 仍然准。

## 投递机制

自建消息对象，不依赖任何 `@deepseek-ai/*` 包：

```js
{ role:'user', content:[{type:'text',text}], source:{kind:'user'}, id: randomUUID() }
→ agent.followup(message)
```

目标会话当作用户发言收到并开始回应（消耗 token）。离线则排队，Agent 上线补发。

## 数据存放与分发

**代码和数据是分开的**，这决定了怎么给别人装。

| 位置 | 内容 | 更新/分发时 |
|---|---|---|
| 插件目录（本 README 所在） | index.js / client.js / package.json / patch.yml | 会被替换 |
| `~/.dsh/session-chat/` | state.json（群组/昵称/配置）、avatars/（头像库）、rooms/（群聊记录） | **不动** |

- 数据目录**首次运行自动创建**（`mkdirSync recursive`），路径基于 `homedir()`，自动适配用户名
- 所以给别人装：**只拷插件目录**，对方机器上会自动生成自己的空白数据
- 你的记录不会跟过去，也不该跟过去
- 同理，重装/升级插件不会丢记录

### 群聊记录

每条消息同时追加到 `~/.dsh/session-chat/rooms/<群名>-<id>.md`，
投递时只带**最近 2 条**（每条截断 120 字）+ 这个文件的完整路径。
群聊越滚越长不会把消息体撑爆，想看全文直接打开文件。

## 排错：三态判读

`diag` 里有一段「磁盘 client.js 检查 ≠ 已加载」，配合版本对照使用：

| 状态 | 含义 | 能否判定 |
|---|---|---|
| ① 检查项缺失 | 根本没写 | ✅ 能判死 |
| ② 有但「运行版本」比磁盘旧 | 写了没重启 | ✅ 能判死 |
| ③ 有且版本一致 | 大概率生效 | ⚠️ 只能给概率，**视觉仍要人看** |

**任何检查工具都只能证明它证明得了的事**——这段输出同理，它不替眼睛。

## 多会话协作：单写者约定

**同一时间只让一个会话改插件源码。**

原因很实在：`index.js` / `client.js` 是同一份文件，两个会话各自读-改-写会互相覆盖，
后写的赢，先写的一整轮操作白做，而且很难发现（文件看起来“正常”）。

建议做法：

| 角色 | 干什么 |
|---|---|
| **写者**（一个会话） | 读代码、改代码、跑测试、打包 |
| **其他人** | 只做验证、看日志、提建议；想催结果就 `poke` 或 `@` 写者 |

判断当前有没有写者：看群里有没有人说“我在改 xxx”，或者插件的版本号是否正在变。

这条不是工具限制，是协作纪律——工具拦不住同时写，只能靠约定。

## 边界

- **只搬文本**，不读不写任何会话工作区文件；存档只读解压取标题。
- **群组、历史、昵称、限流、路由配置都落盘** 到 `~/.dsh/session-chat/state.json`，
  DSH 重启后自动恢复；历史保留最近 200 条（`maxHistory`）。
- 群主是建群的人，只有群主能拉人踢人。
- **群主退群时按「最早加入」接班**（记录在每个成员的 joinedAt 上），
  不是按集合顺序 —— 会话重启后重新加入会排到队尾，用顺序会随机换主。
- 群主可以用 `transfer_owner` 手动指定接班人。
- 群里没人了就解散。
- 限流按**会话**计，A 用完不影响 B。
- 落盘目录可用 config `stateDir` 覆盖。

## 技术备注

**多帧 zstd**：会话是 `session.v4.jsonl.zstd`，每个事件一帧（单文件实测 179 帧）。
整块解压只出第一帧，必须按 magic `28 B5 2F FD` 切帧逐帧解；只解前 40 帧够取标题。
首次扫描 331 个约 1 秒，mtime 缓存后约 25ms。

**面板通道**：Host 用 `ctx.inject(['webServer'], ...)` 等服务就绪后注册
`/dsh-session-chat-api`（不能直接 `ctx.get`，那时服务还没起来，路由会静默不挂）。

## 排错

- 面板报 `HTTP xxx · 响应为空` → Host 路由没挂上：执行 `session_chat` 的 `action=diag`。
- `diag` 显示 `mounted` 但面板仍异常 → Web 端产物问题，重启 DSH 或卸载重装。
- `diag` 显示 `waiting-for-webserver` → webServer 没就绪，属于插件侧问题。
